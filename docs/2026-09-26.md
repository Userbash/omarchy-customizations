# Desktop widget redesign and repository audit

Date: 26 September 2026

This note records the dashboard redesign, the related reliability changes in
the current publication candidate, and the checks performed on this checkout.

## Design references

The visual direction follows the supplied Pixso walkthrough, starting at
[01:35 in the YouTube video](https://www.youtube.com/watch?v=J4LdlUgOGe8&t=95s),
and the LumiHome light and dark interface references. The design uses grouped
sections, repeated card geometry, clear primary values, subdued secondary
details, a violet interaction accent, and green for active states.

The smart-home reference is used for its layout and interaction patterns. The
widget continues to display the real weather, system, network, and MPRIS data
available on the desktop; it does not add fake rooms or device controls.

## Dashboard structure

The desktop applet presents three default sections:

1. **Weather** uses one wide tile for temperature and current conditions, with
   apparent temperature, humidity, precipitation, and wind beneath.
2. **System** uses a two-column grid for CPU load, GPU load, CPU temperature,
   and network throughput. Utilization values include compact progress tracks.
3. **Media** uses a wide card for the current track, artist, playback state,
   progress, transport controls, and player volume.

The visual hierarchy is shared by the light and dark themes. Matte surfaces,
subtle borders, consistent spacing, and rounded corners keep the dashboard
readable over its background. The wallpaper remains behind the panel and cards;
separate opacity controls let the user tune the wallpaper, main panel, and tile
surfaces independently.

## Layout editor

The **Configure** mode separates editing from normal use so dragging a tile
cannot accidentally activate the player. The editor provides the following
operations:

- Create, rename, reorder, and delete sections. Drag a section by its grip;
  drag a tile by its card. The model accepts at most 13 sections.
- Add a built-in tile from the catalog, remove it, reorder it in its section,
  or drag it to another section. Dropping into an empty section appends it.
  The media player remains in the protected Media section and cannot be moved
  separately from its section.
- Resize supported tiles from one to two columns and one to two rows. The media
  player keeps a two-column minimum so its controls remain usable.
- Reset one tile's size with its reset button or by double-clicking the tile;
  reset all tile sizes or restore the complete default layout.
- Lock and unlock section and tile movement to prevent accidental drags. Drag
  feedback lifts and slightly enlarges the active card, then animates it into
  its new position.
- Switch between layout and appearance settings. The **Done** button returns
  to the dashboard. The two-column action grid keeps labels readable. The
  standard settings fit without scrolling; scrolling appears only when custom
  sections make the editor taller than the available screen.

The layout is stored in
`$XDG_STATE_HOME/omarchy/widgets/layout.json`, falling back to
`~/.local/state/omarchy/widgets/layout.json`. The version 3 model migrates
version 1 section maps and version 2 layouts, persists the movement lock, and
keeps the player in Media. It clamps sizes and opacity, rejects unknown and
duplicate tile identifiers, and limits section identifiers and titles. The
version 1 migration restores missing built-in tiles to their default sections;
later layouts preserve tiles the user intentionally removed.

## Theme and appearance

The dashboard supports automatic, light, and dark modes. Appearance settings
include:

- Two bundled SVG wallpaper choices for each theme: sakura and evening for
  light mode, orbit and forest for dark mode.
- Independent wallpaper opacity for light and dark mode.
- Separate opacity values for the dashboard panel and tile surfaces. Values
  are normalized between 0.65 and 1.00 so text remains legible.
- Minimal monochrome or color weather symbols.

The selected wallpaper, icon set, theme, and opacity values are persisted with
the layout. Selecting a wallpaper changes the decoration behind the cards; it
does not create a foreground window or intercept input.

## Media player behavior

The player uses `playerctl` and keeps metadata, transport, seek, and volume
commands bound to the same selected MPRIS player. Its card displays the track,
artist, state, elapsed time, and remaining time. The progress slider seeks to a
specific position; the adjacent controls seek by 10 seconds in either
direction.

One central button toggles play and pause. A right click or long press sends
Stop. The compact volume row contains a speaker mute toggle, decrement and
increment buttons, a slider, and a percentage readout. Slider and button
changes update the MPRIS player's own volume, not the system mixer. The mute
toggle remembers the last non-zero level. The helper validates arguments,
rejects unsupported player identifiers, clamps volume to 0 through 100
percent, and passes commands as argument arrays rather than shell fragments.

Volume writes are serialized. If the user changes the slider repeatedly while
a command is still running, the newest value is applied after the current
write. The slider keeps pointer input during a drag so the parent scrolling
container cannot cancel it. Stale reads do not overwrite a pending write or an
active adjustment, and the percentage is refreshed from the selected MPRIS
player after each write.

## Related changes in this publication candidate

### Installer and uninstall safety

The shared installer code now canonicalizes the selected home directory,
restricts managed paths to the repository's allowlist, rejects unsafe
symbolic-link parents, and validates backup manifests before restoring files.
It rejects path traversal, duplicate or overlapping entries, unexpected file
types, and unknown systemd units. Backup directories and state records are
created with restrictive permissions. The isolated installer tests now cover
symlinked parent paths, malicious backup manifests, rollback after a failed
install, and restoration of files that existed before installation.

### VPN monitor

The status response now computes VPN diagnostics once per request instead of
repeating the same probe. Interface names are validated before being passed to
`wg` or `curl`; local SOCKS proxy URLs must be unauthenticated and use a valid
port. HTTP diagnostics have both a time limit and a response-size limit.

### Weather and KVM metrics

Weather coordinates are parsed as finite numeric values and checked against
latitude and longitude bounds. Location names are limited to 128 characters,
refresh intervals are clamped to 1 through 1,440 minutes, and weather and
geocoding downloads have response-size limits. The KVM metrics helper accepts
alternate `/proc`, network sysfs, and device paths for isolated fixtures and
uses `jq` to produce correctly escaped JSON.

### Clipboard capture

Clipboard reads now have bounded time and size limits: text is capped at
256 KiB, images at 2 MiB, and at most 100 cached images are kept. Only known
image MIME types are written; cached files are deduplicated by content hash and
stored in a private directory. Preview images request a size appropriate to
the display pixel ratio. The unsupported Save As and Pin controls and shortcuts
were removed so the overlay only exposes implemented actions.

### Notification images

Notification-provided image sources are validated before reaching QML image
components. Remote URLs are rejected, while safe local files, Qt image
providers, resource URLs, and app icon theme names remain supported. Local
image paths are escaped when converted to file URLs, and persisted history
copies local images instead of retaining sender-controlled remote sources.

### Hyprland settings and regression coverage

The monitor override validates `OMARCHY_SCALE` and rejects blank, oversized,
or control-character monitor names. The widget layer keeps a subtle wallpaper
blur. The repository test runner now includes focused coverage for clipboard
capture, KVM JSON output, player arguments and volume, weather input
validation, widget layout normalization, notification image sources, and
installer rollback and path validation.

## Verification

`bash scripts/check.sh` passed on 26 September 2026. It includes shell syntax,
JSON manifest, systemd unit, backend, notification, weather, widget layout,
widget QML wiring and IPC end-to-end, installer, KVM, player, clipboard, music
desktop, and game-guard checks. The run reported 76 backend tests and 10
game-guard unit tests passing. The isolated install/uninstall test also passed
its symlink, manifest, and rollback cases.

The widget was additionally loaded in Quickshell and exercised through its
isolated IPC test harness. That scenario covered section and tile editing,
cross-section moves, the movement lock, sizing and reset, theme and wallpaper
selection, opacity, weather icon choice, a nine-field weather-backend record,
saved layout, player transport, seeking, and volume readback against a fake
MPRIS player. A separate temporary
layer-shell instance was tested with physical pointer input: section reorder,
cross-section and same-section tile moves, lock, resize, double-click reset,
volume slider and buttons, mute, play/pause, skip, seek, and Stop all changed
the isolated test state as expected. The real desktop player and mixer volume
were not changed. The installed widget plugin hot-reloaded in Quickshell without
QML load errors, and the installed weather backend returned its expected
nine-field line in a read-only check.

`qmllint`, `qmltestrunner`, `wtype`, and `shellcheck` are not installed in the
current environment, so `scripts/check.sh` reported those optional checks as
skipped. The separate pointer pass used a temporary virtual input device; it
did not depend on `wtype` and did not write to the real player's volume.

The live VPN speed test is documented separately in [tests/README.md](../tests/README.md)
because it transfers data through an active tunnel. The regular suite does not
start or stop a VPN connection.
